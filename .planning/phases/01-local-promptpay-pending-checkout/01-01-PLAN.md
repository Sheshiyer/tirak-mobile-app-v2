<threat_model>
Assets: Bearer token, owned booking ID, charge ID, QR URL, payment attempt state.
Trust boundaries: persisted mobile state -> authenticated Tirak backend -> Omise; Phase 1 mobile code crosses only the first boundary.
Threats: client amount tampering, stale charge leakage between bookings/users, duplicate charge creation, optimistic paid state, authorization/QR logging, and unsafe error detail.
Mitigations: no amount/currency input, confirmed-booking guard, one in-flight mutation, reset on booking reset/auth change, allowlisted response fields, stable safe errors, and no full request/response logging.
Security gate: any source path that accepts a client amount/currency, logs authorization/QR content, or permits local successful state is a blocking defect.
</threat_model>
